---
title: For teachers
description: Turn a course repository into an exercise, hand it out, and collect the submissions.
---

A Yukibana exercise is an ordinary project in a Git repository (an sbt or Cargo
project with its tests) plus a [`yukibana.json`](/docs/reference/yukibana-json)
at its root, which says how the IDE should look, which files students may not
change, and which tests they must never see.

<Steps>
<Step>

### Get a teacher account

Log in at [cloud.yukibana.dev](https://cloud.yukibana.dev). If you haven't received a teacher
invite link, ask an administrator to give you the teacher role, so you can create courses.

</Step>
<Step>

### Create a course, an edition and a project

A **course** groups its **editions**, one per semester or year. In an edition,
create a **project** for each exercise and set its dates: when it opens, its
deadline, and optionally when it closes.

Enrol students and assistants by email address on the edition's roster, before
or after they ever log in. See [Courses and roles](/docs/cloud/courses-and-roles).

</Step>
<Step>

### Link a GitHub repository

- On the Releases page of your project, create a new repository from a template if you don't already have one.
- Install the [Yukibana Cloud GitHub App](https://github.com/apps/yukibana-cloud/installations/select_target) on the repository.
- Select your repository to link on releases page in Yukibana Cloud.

</Step>
<Step>

### Describe the exercise in `yukibana.json`

```json title="yukibana.json"
{
  "$schema": "https://cloud.yukibana.dev/schema/yukibana.json",
  "version": 1,
  "kind": "scala-sbt",
  "features": { "codeSuggestions": false, "squiggles": true, "ai": false },
  "openFiles": ["src/main/scala/Main.scala"],
  "readOnly": ["src/test/**", "ASSIGNMENT.md", "yukibana.json"],
  "hidden": ["src/test/scala/hidden"]
}
```
See the [full reference](/docs/reference/yukibana-json) for more details.

Write the instructions in `ASSIGNMENT.md`: students see it rendered in its own
panel when the project opens.

</Step>
<Step>

### Publish a release

Push a new tag to the repository, and let the CI handle push the release to Yukibana Cloud.
Alternatively, you can also publish releases manually from the CLI, or set up releases any time you
push to the repository (just modify the CI workflow to trigger the action elsewhere).

</Step>
<Step>

### Collect and grade

In the Submissions tab of a project, you will see the list of students who submitted the project.
You can download individual submissions or all at once, with each student's submission in a separate
folder.

Alternatively, you can use the CLI to perform these actions.

</Step>
</Steps>

<Callout title="One repository, many years">
  A new edition is a copy of the previous one: projects and staff come along,
  students and dates do not. Reusing an assignment next year can be done by duplicating the
  course edition.
</Callout>
